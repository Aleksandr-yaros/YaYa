# AIA — протокол сохранения знаний в GitHub

AIA = система, по которой ИИ-агент превращает важные решения из диалога в проверяемые версии GitHub.

## Главная цель

Ни одно важное решение не должно оставаться только в чате. После команды сохранения агент обязан записать результат в репозиторий `Aleksandr-yaros/YaYa`, обновить версию и показать доказательство сохранения.

## Команды владельца

### 1. `AIA: СОХРАНИ`
Сохраняет текущее важное решение.

Рекомендуемый формат:

```text
AIA: СОХРАНИ
Тема: <название>
Тип: идея | решение | ТЗ | архитектура | оборудование | бизнес-модель
Статус: черновик | проверено | утверждено
Что считать главным: <1–3 предложения>
```

### 2. `AIA: АПГРЕЙД`
Обновляет уже существующую тему и повышает версию.

```text
AIA: АПГРЕЙД
Тема: <название существующего блока>
Что изменилось: <конкретные улучшения>
Причина: <почему новая версия лучше>
Статус: проверено | утверждено
```

### 3. `ГДЕ Я?`
Показывает:

- текущую версию;
- кодовое имя;
- дату сохранения;
- последний commit;
- что добавлено в последнем апгрейде;
- незавершённые блоки;
- один лучший следующий шаг.

### 4. `AIA: ДОСТАНЬ <тема>`
Находит сохранённый материал по индексу и возвращает последнюю утверждённую версию.

### 5. `AIA: ЭВОЛЮЦИЯ <тема>`
Показывает, как тема менялась по версиям и commit.

## Правило версий

Используется схема `MAJOR.MINOR.PATCH`:

- `MAJOR` — изменена основная модель проекта или архитектура;
- `MINOR` — добавлен новый модуль или крупная возможность;
- `PATCH` — уточнение, исправление или небольшое улучшение.

Примеры:

- `1.0.0` — первая сохранённая основа;
- `1.1.0` — добавлена система AIA;
- `1.1.1` — исправлена формулировка или индекс;
- `2.0.0` — полностью новая архитектура ЯЯ.

## Что агент обязан сделать при каждом сохранении

1. Определить тему и тип материала.
2. Найти существующий файл или создать новый.
3. Записать не переписку целиком, а очищенное итоговое решение.
4. Указать статус: `draft`, `reviewed` или `approved`.
5. Обновить `docs/INDEX.md`.
6. Обновить `CHANGELOG.md`.
7. Обновить `VERSION.json`.
8. Сделать понятный GitHub commit.
9. Вернуть пользователю версию, commit SHA и список изменённых файлов.

## Защита от потери и путаницы

- GitHub `main` — источник правды.
- Память чата не считается окончательным хранилищем.
- Утверждённый материал нельзя молча заменять: нужен новый commit и новая версия.
- Черновик должен быть помечен как черновик.
- Одна тема должна иметь постоянный ID.

## Постоянные ID

Примеры:

- `YAYA-CORE` — ядро проекта;
- `YAYA-LOYALTY` — лояльность и ЯЯ-баллы;
- `YAYA-PAY` — платежи и QR;
- `YAYA-HARDWARE` — оборудование;
- `YAYA-VOICE` — голос и ИИ;
- `YAYA-CALL` — колл-центр;
- `YAYA-CONTRACTS` — договоры;
- `YAYA-AIA` — система хранения и версий.

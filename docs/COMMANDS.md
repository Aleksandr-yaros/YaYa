# Команды агента ЯЯ

## 1. «Привет, Яя. <задание>»

Главная команда внутреннего агента-маршрутизатора.

Агент обязан:

1. Определить объект, проект и смысл задания.
2. Классифицировать чувствительность данных.
3. Выбрать репозиторий-источник истины.
4. Проверить доступность и видимость репозитория.
5. Предложить точный путь и имя файла.
6. Если подходящего репозитория нет — предложить новый репозиторий, его техническое имя, видимость, структуру и права.
7. Для C2–C4 явно указать C и E.
8. До записи показать риск, откат и Commit Boundary.
9. После подтверждения выполнить запись и вернуть commit SHA.

Канон маршрутизации описан в `docs/YAYA_REPOSITORY_ROUTER.md`.

## 2. «Где я?»

Главная команда состояния проекта.

Агент обязан:

- открыть `VERSION.json`;
- проверить последние изменения в `main`;
- назвать точную версию;
- показать дату сохранения;
- дать краткое состояние проекта;
- перечислить последние зафиксированные решения;
- показать открытые задачи;
- предложить один лучший следующий шаг.

Формат ответа:

```text
ЯЯ vX.Y.Z — <кодовое имя>
Статус: <статус>
Сохранено: <дата>

Что уже есть:
1. ...
2. ...

Что не завершено:
1. ...

Следующий лучший шаг:
...
```

## 3. «Сохрани версию»

Агент должен:

1. Собрать изменения текущего задания.
2. Присвоить новую версию.
3. Обновить `VERSION.json`.
4. Добавить или обновить тематический файл в `docs/`.
5. Обновить `docs/INDEX.md`.
6. Сделать отдельный понятный commit.
7. Сообщить SHA commit и перечень сохранённого.

## 4. «Достань задание <тема>»

Агент должен искать тему по `docs/INDEX.md`, затем открыть связанный файл и вернуть:

- суть;
- последнюю утверждённую формулировку;
- решения;
- незавершённые вопросы;
- ссылки на связанные документы.

## 5. «Покажи эволюцию <тема>»

Агент должен показать историю изменений темы по версиям и commit, объяснив, что стало лучше и почему.

## 6. «Усиль по Salim на 10»

Агент обязан применить формулу:

`SLM = (B × C × E) × V × ΔM × L × R × T × A`

и усилить бизнес-пользу, доказательность, скорость ценности, жизненный цикл, устойчивость, стоимость владения и ответственность/Аманат.

## Правило точности

GitHub является источником правды. Если информация из памяти расходится с файлами репозитория, приоритет имеет последняя сохранённая версия в ветке `main`.

## Запрет молчаливых записей

Любая существенная запись выполняется только после явного Commit Boundary. Для договоров и иных юридически значимых материалов требуется приватный репозиторий, C3 или выше и E3 или выше.

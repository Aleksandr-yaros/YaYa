Версия: **1.0.0**

Класс: **C3 / E4**  
Источник перечня: подключённый GitHub аккаунта `Aleksandr-yaros`.

## 1. Главное правило

Каждый проект хранится отдельно. Один оригинал имеет одного владельца жизненного цикла и один источник истины. `Aleksandr-yaros/YaYa` — маршрутизатор и реестр, а не общий склад материалов.

## 4. Ключевые слова маршрутизации

### Договоры Ярос → `dogovory`

Сильные признаки: `договор`, `договоры`, `акт`, `допсоглашение`, `приложение к договору`, `протокол разногласий`, `претензия`, `доверенность`, `юридический документ`, `юридический оригинал`, `скан договора`, `подпись`, `реквизиты стороны`.

Слово `документ` само по себе не является достаточным юридическим признаком. Если проект уже понятен из контекста — документ идёт в этот проект. Если проект неясен и выбор меняет приватность или репозиторий — допускается один уточняющий вопрос.

### Фабрика ботов ЯЯ

Сильные признаки: `фабрика ботов`, `фабрика сотрудников`, `электронный сотрудник`, `бот`, `промпт`, `роль`, `агент`, `SPEC`, `SPEC·GUARD`, `LEXA`, `ORLIKIN`, `SPIDER`, `IMPACT`, `production prompt`, `релиз бота`.

Рабочее и непроверенное → `logos-pandre`. Утверждённое после проверки и Commit Boundary → `logos-fabric`.

### YaKassa

Сильные признаки: `YaKassa`, `Якасса`, `КП YaKassa`, `коммерческое предложение YaKassa`, `клиент YaKassa`, `рабочий архив YaKassa`.

### CallCenter

Сильные признаки: `CallCenter`, `call center`, `колл-центр`, `контакт-центр`. Маршрут только в отдельный проект CallCenter. Пока репозиторий public, чувствительные материалы блокируются до перевода в private или выбора другого private-контура.

### ЯЯ Оплата

Сильные признаки: `ЯЯ Оплата`, `QR`, `ePOS`, `платёж`, `возврат`, `чек`, `сверка`, `баллы ЯЯ`. Пока `YaYa-Pay` отсутствует, рабочий оригинал получает `BLOCKED_BY_REPOSITORY`.

### ЯЯ Реестр

Сильные признаки: `архитектура`, `правило`, `канон`, `маршрутизация`, `карта проектов`, `версия системы`, `Где я?`, `ADR`, `источник истины`, `стандарт GitHub`.

## 5. Порядок выбора репозитория

1. Явно названный проект или репозиторий.
2. Текущий активный проект разговора.
3. Сильные ключевые слова материала.
4. Владелец жизненного цикла.
5. Требуемая приватность.
6. Если остаётся существенная неоднозначность — один вопрос до записи.

Public-репозиторий никогда не выигрывает у private-контура только из-за совпадения имени.

## 6. Разделение Фабрики ботов

```text
идея / черновик / эксперимент
        ↓
LOGOS·PANDRE
        ↓
LEXA → ORLIKIN·SPIDER → SPEC → SPEC·GUARD → Test → IMPACT → dry-run
        ↓
Commit Boundary
        ↓
LOGOS·FABRIC
        ↓
release / observability / rollback
```

## 7. Правило новых проектов

Если появляется новый самостоятельный проект, для него создаётся отдельный репозиторий. В `YaYa` сохраняются только паспорт проекта, ключевые слова маршрутизации, privacy-класс, ссылка на репозиторий и межпроектные ADR.

## 8. Аудит рассинхронизации

На 2026-08-08 GitHub показывает существующими `logos-pandre` и `logos-fabric`; старые записи реестра, где они назывались физически не созданными, считаются устаревшими и подлежат синхронизации.

## 9. Запреты

- не складывать все проекты в `YaYa`;
- не хранить договоры в public `Dogovora`;
- не смешивать черновик и чистовик Фабрики;
- не использовать `Pesochnica` и безымянные legacy-репозитории как автоматический запасной склад;
- не копировать один оригинал в несколько репозиториев;
- не сохранять секреты, ключи и пароли в Git.

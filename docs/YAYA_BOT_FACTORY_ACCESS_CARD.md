# Фабрика ботов ЯЯ — карточка обращения

Статус: **approved permanent canon**  
Версия карточки: **1.0.0**  
Версия Фабрики: **0.4.0**  
Версия ЯЯ Реестра: **2.8.0**  
Кодовое имя: **Factory Address Protocol**  
Дата: **2026-08-06**  
Владелец: **Александр / Ярос**

## 1. Главное обращение

```text
Яя, Фабрика ботов ЯЯ: <НАМЕРЕНИЕ> <задание>.
```

Где `<НАМЕРЕНИЕ>` — один из канонических глаголов:

- `ДОСТАНЬ` — найти и показать сохранённое;
- `СТАТУС` — показать состояние, версию, риски и следующий шаг;
- `ПРОАНАЛИЗИРУЙ` — изучить задачу без создания рабочего оригинала;
- `СПРОЕКТИРУЙ` — подготовить архитектуру, паспорт и SPEC;
- `СОЗДАЙ` — сформировать пакет электронного сотрудника;
- `ПРОВЕРЬ` — провести SPEC·GUARD, тесты, IMPACT или аудит;
- `СОХРАНИ` — сохранить утверждённые изменения после маршрутизации;
- `ВЫПУСТИ` — подготовить или выполнить контролируемый релиз;
- `УЛУЧШИ` — выполнить апгрейд с новой версией;
- `ОСТАНОВИ` — остановить выпуск или эксплуатацию и применить безопасный откат;
- `АРХИВИРУЙ` — завершить жизненный цикл без потери истории.

## 2. Команда извлечения обращения

Полная форма:

```text
Яя, ЯЯ Реестр: ДОСТАНЬ ОБРАЩЕНИЕ «Фабрика ботов ЯЯ».
```

Прямая форма:

```text
Яя, Фабрика ботов ЯЯ: ДОСТАНЬ ОБРАЩЕНИЕ.
```

Короткая форма:

```text
Яя, база номер два: ДОСТАНЬ ОБРАЩЕНИЕ.
```

Ответ должен содержать:

- каноническое имя;
- текущую версию Фабрики;
- главное обращение;
- допустимые алиасы;
- список намерений;
- мастер-команду;
- источник истины;
- статус репозитория;
- последний commit SHA;
- лучший следующий шаг.

## 3. Три уровня обращения

### Уровень 1 — естественный

```text
Яя, Фабрика ботов ЯЯ: СОЗДАЙ электронного продавца для Telegram.
```

Используется для быстрого старта. Недостающие параметры оформляются как явные предположения.

### Уровень 2 — управляемый

```text
Яя, Фабрика ботов ЯЯ: СОЗДАЙ электронного продавца.
Цель: увеличить конверсию входящих обращений.
Пользователи: клиенты компании «Ярос».
Канал: Telegram.
Интеграции: 1С и CRM.
Разрешено: консультировать, собирать заявку, создавать лид.
Запрещено: обещать цену без подтверждения, принимать финансовые решения.
Результат: паспорт, SPEC, политики, тесты и план dry-run.
```

Это рекомендуемый повседневный формат.

### Уровень 3 — промышленный

```text
Яя, Фабрика ботов ЯЯ: СОЗДАЙ электронного продавца как производственный заказ.
Режим: полный цикл.
Бизнес-результат: <измеримый результат>.
Пользователи: <кто использует>.
Канал: <Telegram / голос / web / другое>.
Интеграции: <1С / CRM / телефония / API>.
Данные и знания: <источники>.
Разрешённые действия: <список>.
Запрещённые действия: <список>.
Ответственный: <владелец>.
Критерий готовности: <проверяемый критерий>.

Примени LEXA, ORLIKIN·SPIDER 8/8, SPEC, SPEC·GUARD, IMPACT и Salim/SLM. Установи C/E, проведи dry-run, покажи риск, стоимость владения и откат. До записи покажи Commit Boundary. После подтверждения сохрани, проверь и верни версию, пути, тесты и commit SHA.
```

Этот формат обязателен для C2–C4 и production-релизов.

## 4. Лучшие обращения по цели

### Получить состояние

```text
Яя, Фабрика ботов ЯЯ: СТАТУС. Покажи версию, сохранённые документы, блокировки, риски и следующий шаг.
```

### Достать итоговое задание

```text
Яя, Фабрика ботов ЯЯ: ДОСТАНЬ итоговое мастер-ТЗ.
```

### Создать сотрудника

```text
Яя, Фабрика ботов ЯЯ: СОЗДАЙ электронного <роль> для <бизнес-цель> в канале <канал>.
```

### Проверить сотрудника

```text
Яя, Фабрика ботов ЯЯ: ПРОВЕРЬ сотрудника <ID> через SPEC·GUARD, IMPACT, негативные тесты и dry-run.
```

### Улучшить

```text
Яя, Фабрика ботов ЯЯ: УЛУЧШИ <объект> до новой версии. Покажи изменения, эффект, C/E, риски и откат; сохрани после Commit Boundary.
```

### Выпустить

```text
Яя, Фабрика ботов ЯЯ: ВЫПУСТИ сотрудника <ID>, только если пройдены release gates, тесты, IMPACT и dry-run.
```

### Аварийно остановить

```text
Яя, Фабрика ботов ЯЯ: ОСТАНОВИ сотрудника <ID>. Зафиксируй причину, отзови полномочия, сохрани аудит и предложи безопасный откат.
```

## 5. Алиасы

Допустимы:

- `Фабрика ботов ЯЯ` — каноническое имя;
- `Фабрика сотрудников ЯЯ`;
- `Фабрика электронных сотрудников ЯЯ`;
- `электронные сотрудники ЯЯ`;
- `Фабрика ботов`;
- `база номер два`.

Каноническое имя имеет высший приоритет. Фраза `база номер два` допустима только внутри экосистемы ЯЯ.

## 6. Правило автоматического усиления

Если пользователь обращается коротко, например:

```text
Яя, Фабрика ботов ЯЯ: создай продавца.
```

Яя обязан внутренне привести запрос к структуре:

`намерение → объект → бизнес-результат → пользователи → канал → данные → права → интеграции → критерии → C/E → риск → откат → Commit Boundary`.

Недостающие сведения отмечаются как предположения. Для C2–C4 запрещено молча утверждать критические предположения.

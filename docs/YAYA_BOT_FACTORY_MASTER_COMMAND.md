Статус: **approved permanent canon**  
Версия команды: **2.0.0**  
Версия Фабрики: **0.4.0**  
Версия ЯЯ Реестра: **2.8.0**  
Кодовое имя: **Factory Address Protocol**  
Дата: **2026-08-06**  
Владелец: **Александр / Ярос**

## 1. Канонический синтаксис

```text
Яя, Фабрика ботов ЯЯ: <НАМЕРЕНИЕ> <задание>.
```

Намерения:

- `ДОСТАНЬ` — извлечь сохранённое;
- `СТАТУС` — показать состояние;
- `ПРОАНАЛИЗИРУЙ` — изучить задачу;
- `СПРОЕКТИРУЙ` — создать архитектуру и SPEC;
- `СОЗДАЙ` — подготовить пакет сотрудника;
- `ПРОВЕРЬ` — провести контроль и тесты;
- `СОХРАНИ` — записать утверждённые изменения;
- `ВЫПУСТИ` — выполнить release gate;
- `УЛУЧШИ` — повысить версию;
- `ОСТАНОВИ` — отозвать права и применить откат;
- `АРХИВИРУЙ` — завершить жизненный цикл.

## 2. Команда «достань обращение»

```text
Яя, Фабрика ботов ЯЯ: ДОСТАНЬ ОБРАЩЕНИЕ.
```

Допустимо:

```text
Яя, ЯЯ Реестр: ДОСТАНЬ ОБРАЩЕНИЕ «Фабрика ботов ЯЯ».
```

```text
Яя, база номер два: ДОСТАНЬ ОБРАЩЕНИЕ.
```

Источник извлечения: `docs/YAYA_BOT_FACTORY_ACCESS_CARD.md`.

## 3. Три уровня обращения

### Простой

```text
Яя, Фабрика ботов ЯЯ: СОЗДАЙ электронного продавца для Telegram.
```

### Управляемый

```text
Яя, Фабрика ботов ЯЯ: СОЗДАЙ электронного продавца.
Цель: <измеримый результат>.
Пользователи: <кто>.
Канал: <где>.
Интеграции: <системы>.
Разрешено: <действия>.
Запрещено: <действия>.
Критерий готовности: <проверяемый результат>.
```

### Промышленный

```text
Яя, Фабрика ботов ЯЯ: СОЗДАЙ <сотрудника> как производственный заказ. Примени LEXA, ORLIKIN·SPIDER 8/8, SPEC, SPEC·GUARD, IMPACT и Salim/SLM. Установи C/E, подготовь тесты, dry-run, наблюдаемость, стоимость владения и откат. До записи покажи Commit Boundary. После подтверждения сохрани, проверь и верни версию, пути и commit SHA.
```

## 4. Производственный цикл

```text
Запрос владельца
→ LEXA
→ ORLIKIN·SPIDER 8/8
→ паспорт
→ SPEC
→ SPEC·GUARD
→ архитектура и политики
→ Build
→ Test
→ IMPACT
→ dry-run
→ подтверждение
→ Commit Boundary
→ Release
→ Observability
→ Improve Desk / Rollback
```

## 5. ORLIKIN·SPIDER

Восемь обязательных контуров:

1. ценность и результат;
2. роль и поведение;
3. данные и знания;
4. права и безопасность;
5. интеграции;
6. качество и доказательство;
7. релиз и наблюдаемость;
8. экономика и Аманат.

Каждая лапа должна иметь результат либо отметку `N/A` с объяснением.

## 7. Жизненный цикл

`IDEA → FRAMED → SPECIFIED → GUARDED → BUILT → TESTED → DRY_RUN_PASSED → APPROVED → RELEASED → OBSERVED → IMPROVING → RETIRED`

Для C2–C4 обязателен gate:

`SPEC·GUARD → IMPACT → dry-run → подтверждение → Commit Boundary`.

## 8. Маршрутизация

Источник истины: private `Aleksandr-yaros/YaYa-Bot-Factory`.

Пока он отсутствует:

- рабочие оригиналы получают `BLOCKED_BY_REPOSITORY`;

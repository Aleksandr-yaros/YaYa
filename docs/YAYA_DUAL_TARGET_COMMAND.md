# ЯЯ — постоянная команда раздельной записи в две базы

Статус: **approved permanent canon**  
Версия команды: **1.0.0**  
Версия реестра: **2.6.0**  
Кодовое имя: **Dual Target Proof**  
Дата: **2026-08-06**  
Владелец: **Александр / Ярос**

## 1. Назначение

Команда применяется, когда пользователь хочет отдельно обратиться к двум проектным базам, создать разные материалы и получить доказательство, что они не смешались.

## 2. Канонический полный запрос

```text
Яя, выполни раздельную запись в два контура.

База 1 — ЯЯ Оплата:
- объект: <что создать или сохранить>;
- формат: <svg/png/md/json/...>;
- целевой путь: <каталог/имя файла>;
- назначение: <для чего нужен материал>.

База 2 — Фабрика ботов ЯЯ:
- объект: <другой материал>;
- формат: <svg/png/md/json/...>;
- целевой путь: <каталог/имя файла>;
- назначение: <для чего нужен материал>.

Обязательно:
1. Не смешивай материалы двух баз.
2. Для каждого объекта отдельно покажи канонический контур, источник истины, репозиторий, путь, C/E, риск и откат.
3. Если целевой репозиторий отсутствует, не выдавай запись в реестр за запись в настоящую базу. Разрешается только явно помеченная демонстрационная запись в проектный каталог реестра.
4. До записи покажи Commit Boundary, если моё сообщение не содержит прямого указания сохранить.
5. После записи проверь оба файла и верни для каждого отдельный commit SHA и ссылку.
6. Усиль решение по Salim/SLM на 10.
```

## 3. Короткая команда

```text
Яя, две базы: в ЯЯ Оплата сохрани <материал 1>, а в Фабрику ботов ЯЯ сохрани <материал 2>. Раздели источники истины, проверь пути и верни два commit SHA.
```

## 4. Пример с картинками

```text
Яя, выполни раздельную запись в два контура.

База 1 — ЯЯ Оплата:
создай SVG-картинку о динамическом QR и подтверждении оплаты; сохрани в `assets/payment-flow.svg`.

База 2 — Фабрика ботов ЯЯ:
создай другую SVG-картинку об электронном сотруднике; сохрани в `assets/electronic-employee.svg`.

Не смешивай изображения. Проверь оба файла и верни отдельные commit SHA.
```

## 5. Правило сохранения при отсутствующих репозиториях

Пока `Aleksandr-yaros/YaYa-Pay` и `Aleksandr-yaros/YaYa-Bot-Factory` физически не созданы:

- постоянные рабочие оригиналы блокируются со статусом `BLOCKED_BY_REPOSITORY`;
- демонстрационные и регистрационные материалы разрешено сохранять только в:
  - `projects/yaya-pay/demo/`;
  - `projects/bot-factory/demo/`;
- каждый такой файл обязан содержать пометку, что это демонстрационный актив реестра, а не оригинал будущего продуктового репозитория;
- после создания репозиториев выполняется контролируемый перенос, а в `YaYa` остаются ссылки и история.

## 6. Доказательство раздельной записи

Ответ после выполнения должен содержать две независимые карточки:

```text
БАЗА 1 · СОХРАНЕНО
Контур: ЯЯ Оплата
Репозиторий: ...
Путь: ...
Commit: ...
Проверка: ...
```

```text
БАЗА 2 · СОХРАНЕНО
Контур: Фабрика ботов ЯЯ
Репозиторий: ...
Путь: ...
Commit: ...
Проверка: ...
```

## 7. Salim/SLM

`SLM = (B × C × E) × V × ΔM × L × R × T × A`

- `B = 10/10`: один запрос управляет двумя базами без смешения;
- `C = C3`, для платёжного материала `C4`;
- `E = E4`: маршруты подтверждаются каноном и фактической проверкой GitHub;
- `V = 10/10`: команда готова для немедленного использования;
- `ΔM = 1.8`: параллельная раздельная работа даёт больше ценности, чем две несвязанные команды;
- `L = 9/10`: учтены создание, проверка, миграция и откат; физические репозитории остаются незавершёнными;
- `R = 9/10`: запрещена имитация записи в отсутствующую базу;
- `T = 9/10`: единый шаблон снижает стоимость ошибок и повторных объяснений;
- `A = 10/10`: каждая запись подтверждается путём, проверкой и commit SHA.

## 8. Постоянное правило понимания

Фразы `обе базы`, `две базы`, `база номер один и база номер два` в контексте ЯЯ по умолчанию означают:

1. база №1 — `ЯЯ Оплата`;
2. база №2 — `Фабрика ботов ЯЯ`.

Если пользователь явно называет другие базы, приоритет имеют явно названные канонические контуры.

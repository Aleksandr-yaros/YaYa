# YAYA Journey Center

Центральный исполняемый контур пользовательских историй YAYA. Он хранит каждый шаг, определяет незавершённые истории, выбирает помощь и разрешает автоматизацию только безопасных действий.

## Контракт 8-шаговой истории

1. `POST /v1/journeys` создаёт историю и все шаги одной пакетной записью.
2. `POST /v1/journeys/{journeyId}/steps/{n}` записывает `view`, `attempt`, `block`, `help`, `complete` или `auto_complete`.
3. `GET /v1/journeys/{journeyId}` возвращает прогресс и нерешённые причины трения.
4. Ежечасный анализ находит истории без активности более 30 минут.
5. Причина и помощь фиксируются в `friction_analysis` и отправляются в PostHog.
6. `safe_auto` может выполнить только безопасный UI-шаг. `manual` и `guided` требуют реального или подтверждённого действия.

## События PostHog

- `yaya_journey_started`
- `yaya_step_completed`
- `yaya_friction_detected`
- `yaya_journey_completed`

## Локальная проверка

```bash
npm install
npm run check
```

## Подключение центра

1. Создать D1 для staging и production, заменить два `database_id`.
2. Применить миграции.
3. Добавить секрет `POSTHOG_API_KEY` отдельно для staging и production.
4. Выполнить dry-run, затем staging deploy.
5. Запустить синтетическую 8-шаговую историю и доказать записи SQL-запросом.

Не хранить в PostHog фискальные реквизиты, платёжные секреты или открытые персональные данные. `actorId` должен быть псевдонимным идентификатором.

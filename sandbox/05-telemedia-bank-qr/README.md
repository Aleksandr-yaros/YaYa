# TELEMEDIA BANK QR — SPIDER SANDBOX

Статус: INTENT / G0 CANDIDATE

## Цель
Защитить и усилить ценность парка Telemedia-терминалов через подключение банковского QR, начиная с минимального доказуемого QR-сценария и затем углубляясь уровнями SPIDER.

## Исходная гипотеза
Терминал должен уметь подключаться к банковскому QR так, чтобы торговая точка могла выбрать/подключить банк, показать QR для оплаты, получить подтверждение, связать оплату с продажей/чеком/сменой и иметь доказуемую историю операции.

## НЕ считать пока доказанным
- точное число активных терминалов;
- статус собственности/госаппаратов;
- список банков и договорные права;
- допустимость конкретной QR-схемы по НБКР;
- API каждого банка;
- схема клиринга/расчётов;
- техническая возможность обновления всего парка.

Эти пункты требуют source evidence перед G1/G2.

## Первая лестница уровней
L0 — INVENTORY: терминал/версия/точка/сеть/обновление известны.
L1 — QR DISPLAY: терминал получает и показывает тестовый QR.
L2 — PAYMENT CORRELATION: payment_id связан с конкретной продажей.
L3 — BANK CALLBACK/POLL: подтверждение банка приходит и проверяется.
L4 — FISCAL LINK: подтверждённая оплата связана с фискальным чеком.
L5 — BANK SELECT: точка выбирает уже подключённый банк без переустановки.
L6 — ONBOARDING: новый банк/мерчант подключается через управляемый сценарий.
L7 — OPERATOR CONTROL: оператор видит терминал, банк, QR, callback, ошибку, retry.
L8 — SHIFT CONTROL: закрытие смены сверяет продажи/оплаты/расхождения.
L9 — MULTI-BANK ROUTING: несколько банков работают через единый canonical contract.
L10 — FLEET ROLLOUT: canary -> партия -> парк, rollback и evidence.

## Первый вертикальный тест
ONE PERFECT QR PAYMENT:
Терминал -> сумма/заказ -> банк -> QR -> клиент платит -> bank confirmation -> correlation -> fiscal action -> success screen -> audit/evidence.

## SPIDER Gate
Каждый уровень имеет 3–4 уникальных mandatory tests + anti-SALYM test. «Почти L5» = L4.

## Первый вопрос песочницы
До дизайна QR-экрана доказать фактическую архитектуру одного реального терминала:
hardware/model -> OS/app version -> connectivity -> update channel -> current payment/fiscal flow -> available bank integration point.
